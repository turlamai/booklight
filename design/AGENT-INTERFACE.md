# Booklight Agent Interface — 产品调用契约草案

版本：0.1 · 2026-11-14 · 状态：设计规格，未实现的接口不构成能力承诺。

目标：成为 AI 时代优秀的 PDF 阅读与工作软件。人和 agent 操作同一份文档、同一套引擎能力与同一份修改记录；agent 无需模拟点击，也不依赖聊天界面常驻。

本文件规定 Booklight 自有的领域契约，不宣称任何 CLI、MCP 服务、URI scheme 或 PDF/OCR 引擎已可用。具体协议适配、命令拼写和版本选择在实现时确定，不能把文中的示意当成已注册工具。

## 1. 产品与架构边界

- GUI、CLI、MCP 共用 Racket 文档引擎和同一语义操作；跨传输契约遵循家族 keel 能力，原生 UI 走 rivet，适用的 WebView UI 走 glaze。浏览器中的本轮 JS 只承载原型演示，不作为产品业务引擎。
- PDF 渲染、文字抽取、阅读顺序、页面坐标、OCR 与图表区域定位属于文档基础能力。第三方库选型和新增家族库先查 catalog，本文件不指定未经评估的实现依赖。
- GUI 可以不打开，已授权 agent 仍应能读取、检索和提交允许范围内的操作。需要人工批准时返回结构化待批准结果，不能阻塞命令等待不存在的窗口。
- 读取、批注、页面编辑、外发分开授权。浏览器原型中的逐项核对是演示路径；正式产品在用户预先授予的操作、文档、次数和期限范围内可自动执行，不强迫每次弹窗。
- PDF 是核心产品；保留既有 EPUB 阅读能力。Agent 能力的商业授权由 permit 承载，commerce 处理商业编排；各操作的免费/付费边界仍待产品定价决策，不在协议里写死。

## 2. 能力发现先于调用

入口应先返回当前引擎实际能力及限制：接口版本、可用操作、支持的文件格式、OCR 是否可用、可抽取的内容类型、并发与批量限制、可用提交语义、是否有 UI、授权模式。

`unsupported` 与 `unauthorized` 必须区分。没有 OCR 不返回假文本；没有页面编辑不能假装另存成功。所有工具名、版本和支持项由运行时报告，agent 不靠静态文档猜测。

建议领域操作：

| 操作 | 主要输入 | 输出与不变式 |
| --- | --- | --- |
| `capabilities.get` | 可接受契约版本 | 当前版本、可用操作、限制、提交粒度 |
| `documents.open` | 用户已授予的文件句柄/资源引用 | 文档标识、版本、格式、页数；不自动上传或复制进书库 |
| `documents.list` | 授权范围、游标 | 只列当前主体可见的文档，不暴露其他文件名称 |
| `documents.describe` | 文档与期望版本 | 元数据、页尺寸、加密状态、解析能力、索引状态 |
| `documents.close` | 文档标识 | 释放会话资源；已授权的长期任务按明确租约处理 |
| `pages.read` | 文档、版本、页范围、内容类型 | 块文本、阅读顺序、区域、提取来源与警告 |
| `regions.read` | 文档、版本、页码、区域 | 区域文字/图像资源引用，保持来源与几何对应 |
| `search.query` | 文档集合、查询、匹配模式、游标 | 带完整 anchor 的命中结果、分页信息、部分失败 |
| `anchors.resolve` | 锚点、目标版本、允许的定位策略 | exact / remapped / ambiguous / unresolved |
| `annotations.list` | 文档、筛选、游标 | 批注、锚点、作者与版本 |
| `changes.prepare` | 一组批注或页面编辑、基准版本 | 提案、前后差异、影响范围、所需权限；无写盘 |
| `changes.commit` | 提案版本、授权/批准凭据、幂等键 | 已提交变更、持久化状态、新版本与撤销信息 |
| `changes.reject` | 提案标识 | 拒绝记录；不改变文档 |
| `changes.undo` | 事务标识、当前基准版本、幂等键 | 逆操作、新版本；版本冲突时不覆盖后续修改 |
| `citations.export` | 引用集合、格式、目标能力句柄 | 文本或授权目标的输出产物，保留原文与来源 |
| `tasks.get` | 任务标识 | 状态、进度、检查点、部分结果与可恢复性 |
| `tasks.cancel` | 任务标识 | 取消已确认/取消中；已提交修改不假装被撤回 |
| `tasks.resume` | 检查点、当前授权与文档版本 | 继续未完成步骤，不重复已有副作用 |
| `events.read` | 任务、最后事件序号 | 有序事件、断档/过期信息与下一游标 |
| `viewer.reveal` | 文档锚点、是否允许打开窗口 | 在 GUI 定位或返回需打开应用的结果；读取不依赖它 |
| `permissions.inspect` | 当前主体 | 当前可见 grant，不返回密钥 |
| `permissions.revoke` | grant 标识 | 撤销结果与受影响任务，及时停止后续读取/写入 |

这不是要求首版一次实现所有操作。首版可用集合必须从 capabilities 明确发现，缺项返回明确不可用，不能用空成功响应代替。

## 3. 标识与版本

### 文档身份

`document_id` 是 Booklight 的不透明标识，不是文件路径，也不是内容摘要。引擎维护用户授权文档与源资源的对应关系。文件移动通过显式重连或文件身份跟踪处理，不能仅凭同名自动替换。

同一份字节内容可能存在不同用户权限和批注上下文，不能仅按内容 hash 合并授权。可选内容摘要用于核验快照，不用作跨用户公开标识。

### 版本分离

- `content_revision`：PDF 字节或解析所依赖的内容快照。
- `annotation_revision`：sidecar 批注的修订。
- `layout_revision`：尚未另存的页面编辑工作副本。
- `extraction_revision`：解析器、OCR 或阅读顺序修订后的文本视图。

正式引擎以不透明修订值而非可预测计数器比较版本。写操作携带所依赖各轴的版本；批注增加不必使原始 PDF 内容锚点失效，但并发批注写入仍检查 annotation_revision。原型简化为单个递增版本，任何修改后都要求重新核对旧提案。

源文件在操作期间外部变化时，引擎保留当前快照或返回冲突，不静默读取一半旧内容一半新内容。快照释放和失效必须有明确事件。

## 4. Anchor：任何结果必须有来处

PDF 文本证据的产品数据结构示意：

```json
{
  "document_id": "doc-example",
  "content_revision": "opaque-content-revision",
  "extraction_revision": "opaque-extraction-revision",
  "page_index": 1,
  "page_label": "2",
  "coordinate_space": "normalized-cropbox-top-left-unrotated",
  "rects": [[0.12, 0.28, 0.76, 0.18]],
  "quote": {
    "exact": "测量条件包括环境温度、振动状态、采样率和采样窗口。",
    "prefix": "",
    "suffix": ""
  },
  "extraction": "embedded_text",
  "confidence": null
}
```

示意数值不是任何真实 PDF 的实测位置。

- `page_index` 从 0 开始；`page_label` 是 PDF 展示标签，可为罗马数字或重复标签，不用于唯一定位。
- rect 为 `[x, y, width, height]`，全部相对未旋转 CropBox 标准化至 0–1，左上原点、向右向下。必须同时提供页尺寸、CropBox、固有旋转和变换信息，以映射 PDF 原生坐标及当前视口。
- 跨行文字使用多个 rect，跨页证据使用多个 anchor。不能用一个跨页矩形冒充精确选区。
- `quote.exact` 保留实际抽取原文；搜索规范化、连字处理、断行合并另有映射，不可悄悄更改引用原句。前后缀用于消除同页重复片段歧义。
- 可选 `block_id`、字符偏移需说明对应 extraction_revision 和 Unicode 索引单位，不依赖 PDF 文件里的不稳定对象顺序。
- 图片、表格、公式用区域引用与资源类型表示。不能把视觉推断当作原生嵌入文字。
- OCR 结果标记 `extraction=ocr`，保留语言、引擎版本、警告与可提供的置信度。无可靠分数时为 null，不编造百分比。
- 重排、OCR 纠正或文件变化后，旧锚点必须 resolve；ambiguous 返回候选，不自动选第一个。跨版本重定位即使成功，也需新提案/符合授权策略的重新核对才能写入。

EPUB 使用资源路径、章节与文本范围等稳定定位，不伪造固定 PDF 页码；统一通过上层引用对象提供回跳。

## 5. 读取、检索与引用

- 页范围、结果条数、资源体积均受限；分页游标绑定查询、文档集合、授权主体与版本快照。范围改变不能复用旧游标。
- 空白页返回明确空文本；扫描页返回 `ocr_required` 或 OCR 任务，不把空字符串解释为“该文件没有内容”。
- `keyword_any`、`keyword_all`、正则或语义检索按 capabilities 支持项显式指定。不可把字符串匹配结果标成语义理解。
- 跨文档结果按声明的排序规则返回，计数注明精确或估计；部分失败列出每文档结果，用户无权访问的文件不能泄露名称。
- 对加密文件、签名、损坏页、异常字形与缺失字体返回可处理的状态。不绕过密码或授权，也不要求 agent 在日志里提交密码。
- 引用包含原句、文档标题、版本、页标签、anchor 与提取来源。模型摘要、用户笔记、原始证据分字段存储，不能混写。
- 回跳链接是定位入口，不是授权凭据；通过链接打开时仍检查文档权限。URI 格式及系统注册尚待实现，不在本轮生成假可用链接。

## 6. 请求、幂等与批量操作

领域请求至少具有 `request_id`、契约版本、操作、参数及所依赖的快照；授权从真实连接上下文提供，不信任参数中自报的用户身份。

写请求必须有 `idempotency_key`。同一授权主体下，相同键与相同规范化请求返回相同提交结果；相同键配不同内容返回 `idempotency_conflict`。键的有效期限、保留策略与查询方式由 capabilities 声明，不能把“未查到”误认为“从未提交”。

`changes.prepare` 不修改文档，输出规范化差异、操作标识、提案修订、基准版本与所需权限。批准凭据绑定提案摘要、目标文档、版本、操作类型、次数、期限与外发目的地（如适用）；提案编辑后旧批准失效。

批量读取可部分成功，逐项给出错误。批量写入必须先声明提交粒度：

- 首版目标是单文档事务；跨多文档按单文档提交并返回完整逐项结果，可从检查点恢复。
- 只有运行时明确支持时，才接受更强的 all-or-nothing 策略。不得用浏览器内存中的同步更新声称实现跨文件原子提交。
- 提交前重查权限、提案版本、文档版本与锚点。冲突不覆盖、不部分隐瞒。
- 写盘采用恢复日志、临时文件与可恢复的替换流程，依据真实文件系统能力承诺保证；进程中断后重启能查询结果。
- 自动重试只适用于读取或带幂等保障的操作；版本冲突与权限撤销必须由 agent 调整计划或请求新授权，不能无限重试。

成功返回 `commit_status`（如 committed / pending_persistence）、新修订、具体变更、输出产物和撤销可用性。只有真正持久化成功才显示“已保存”；导出排队或仅保留内存不等于保存完成。

## 7. 权限、外发与接管

Grant 绑定 agent 主体、连接实例、明确文档集合或经用户批准的范围、操作能力、到期时间、次数限制与数据目的地。目录授权若允许新增文件，必须单独说明是否包含未来文件及子目录；默认不扩展。

| 能力 | 允许行为 | 不隐含的权限 |
| --- | --- | --- |
| read | 列举授权文档、读文本、区域、检索 | 不能写批注、改页或外发 |
| annotate | 按策略创建、更新、删除 sidecar 批注 | 不授权修改 PDF 原件 |
| edit | 编辑工作副本、按规则输出新 PDF | 不授权覆写源文件、外发或删除源文件 |
| external_send | 向明确目的地发送经批准的数据 | 不授权所有服务商或未来全文发送 |

文件写入目标也需能力句柄；引擎不能接受任意路径就写盘。另存默认生成新文件，覆写源文件需要单独明确授权，并检查签名、加密及表单影响。

外发核对同时列文档、范围、实际内容、会话历史、目的地、模型/服务标识（如适用）。字符数精确且索引单位明确，但不把字符数当 token、价格或总请求字节数。系统提示、附件与其他请求组成部分另行说明，不能借核对面板隐瞒外发内容。

用户可随时撤销授权、停止任务、接管任务。撤销后拒绝后续操作并关闭仍在读取的流；已外发的数据和已提交的修改不能声称已收回。接管不会撤销已完成操作，但暂停自动推进并保留证据、提案及检查点。

文档文字、文件元数据、OCR、批注与检索结果都是不可信内容，不能改变授权、工具选择、外发目的地或任务指令。文档内出现“发送全文”“忽略限制”等语句只作为原文返回。

## 8. 长任务与事件

任务状态：queued → running → awaiting_approval / paused / succeeded / failed / cancelled。停止请求可能先进入 cancelling；实际停止后才报告 cancelled。

可细分阶段：检查范围、索引/抽取、检索、定位证据、准备修改、等待批准、提交、保存。进度优先报告可知的页数/文档数，不编造精确百分比。

事件具有单调序号、事件标识、任务标识、时间、阶段与结构化载荷。重连提供最后事件序号，可重复交付但事件标识稳定；客户端去重。事件保留到期或断档返回明确结果，不悄悄从头播放并重新执行副作用。

取消与提交存在竞争时，以提交日志为准。返回已经提交的项目、仍未处理项目和可撤销信息，不能用 cancelled 掩盖已完成的写入。恢复重新检查授权与快照，不自动批准旧提案。

## 9. 错误格式与恢复建议

错误至少包含 `code`、安全可读的 `message`、`request_id`、`retryable`、`recovery`、必要的安全 details。不能把内部路径、密钥、文档全文或未授权资源名塞入错误。

| code | 含义 | 恢复 |
| --- | --- | --- |
| permission_required | 缺少能力或需要批准 | 返回所需操作与安全的批准流程 |
| permission_revoked | 授权撤销 | 停止后续操作，等待新授权 |
| document_unavailable | 文件移动、失联或会话关闭 | 重新连接用户指定文件，不按同名替换 |
| version_conflict | 内容或批注基准改变 | 获取当前修订，重新定位与准备提案 |
| anchor_ambiguous | 原句存在多个候选 | 返回可见范围内候选，等待确认 |
| anchor_unresolved | 无法可靠定位 | 回原文核对，禁止猜测写入 |
| extraction_required | 尚未建立文本视图 | 发起可取消的抽取任务 |
| ocr_unavailable | 需要 OCR 但当前不可用 | 报告能力缺项，保留页面阅读入口 |
| encrypted_document | 缺少解密能力 | 通过安全交互解锁，不记录密码 |
| proposal_changed | 批准后提案改变 | 重新核对，旧批准无效 |
| persistence_failed | 修改未成功写盘 | 保留恢复副本，重试或导出 |
| idempotency_conflict | 同键请求内容不同 | 查询旧请求或使用新的业务操作键 |
| unsupported | 当前实现不支持 | 使用已发现的能力或如实终止 |
| cancelled | 任务已停止 | 查看部分结果与已提交事务 |

## 10. 审计与隐私

记录主体、授权决策、操作、时间、受影响文档标识与版本、提案摘要、结果、事务与撤销关系。默认不在日志中记录全文、API Key、密码、完整本地路径或外发凭据。

任务证据包与普通诊断日志区分：证据包可包含用户主动导出的原句与笔记，导出前应说明范围；诊断日志不自动附带。批注由 agent 创建应保留来源主体，用户编辑后另记修订，不冒充用户亲笔。

## 11. 首个完整切片

用户授权两份 PDF 的读取范围 → agent 检索测量条件 → 返回原句和精确位置 → 创建批注提案 → 用户在阅读器核对 → 在授权内或一次性批准后提交 → 回原文看批注 → 可撤销并导出记录。

实现要求：

1. 同一操作分别通过 GUI、CLI、MCP 执行，返回相同领域结果。
2. 真实 PDF 中验证多栏、连字、旋转、扫描页、公式、跨页和重复原句；无法确定时返回歧义而非猜测。
3. 并发 GUI 修改、外部文件变化、断线重连、重复提交与进程中断都有可解释结果。
4. 覆盖授权撤销、越界读取、隐式外发与恶意文档内容；产物与日志扫描不得泄漏凭据或未授权内容。
5. 批注 sidecar 与 PDF 另存的持久化失败有恢复出口；真实输出需验证，不能只检查 UI 显示成功。

以上为后续工程验证要求，本轮未执行这些验证，也未交付引擎实现。

## 12. 本轮原型映射

`prototype/agent.html` 是任务入口；所有现有页面右上角可进入 Agent。设置中管理本地示例主体的会话授权。

演示语料为《光学实验记录》和《复测与误差核对》两份自编 PDF 版式示例，各三页。它们不是磁盘上的 PDF 文件，文本和位置由示例数据编排，不表示已完成真实抽取。

原型支持：关键词检索、分阶段进度、停止、接管、撤销授权后的失败与恢复、证据回跳、可编辑批注提案、页面方向提案、批量核对、一次性批准、应用、拒绝、版本过期阻断、刷新核对、撤销和 JSON 任务记录导出。

任务、授权、Agent 批注、页面修改、审计在当前页面会话内保存，刷新即失效；可主动导出记录。本轮没有运行服务、真实凭据、后台 agent、CLI/MCP 适配、PDF/OCR 或外发能力。原型能力不能替代正式接口能力发现。
